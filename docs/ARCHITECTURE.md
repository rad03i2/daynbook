# DaynBook Architecture

## هدف التصميم

DaynBook نظام دفتر ديون يعمل محليًا أولًا. تسجيل الدين أو التسديد لا ينتظر الشبكة ولا يعتمد على نجاح خدمة سحابية خارجية.

## طبقات النظام

1. **Presentation** — واجهات الهاتف والتابلت العربية.
2. **Application** — حالة الشاشة وعمليات المستخدم عبر `LedgerController`.
3. **Local Data** — قاعدة SQLite وهي مصدر الحقيقة أثناء الاستخدام اليومي.
4. **Cloud Backup** — نسخة احتياطية مستقلة في Google Drive، تضاف في المرحلة الثانية.
5. **Background Jobs** — جدولة النسخ عبر WorkManager مع احترام قيود Android على المهام الخلفية.

## قواعد سلامة البيانات

- كل زبون يملك `UUID` ثابتًا.
- كل حركة مالية تملك `UUID` مستقلًا ولا تعدل الرصيد مباشرة.
- الدين قيمة موجبة من نوع `debt` والتسديد قيمة موجبة من نوع `payment`.
- الرصيد يُشتق حسابيًا: `debt - payment`.
- المبالغ تخزن كأعداد صحيحة بالدينار العراقي.
- حذف الزبون سيحذف حركاته فقط إذا تم تنفيذ عملية حذف صريحة مستقبلًا.
- Foreign Keys مفعلة في SQLite.

## استراتيجية النسخ الاحتياطي القادمة

سيتم إنشاء snapshot متناسق لقاعدة البيانات ثم تشفيره قبل الرفع. تحفظ بيانات وصفية مع النسخة مثل:

- schemaVersion
- appVersion
- createdAt
- deviceId غير حساس
- checksum للتحقق من سلامة الملف

الاستعادة يجب أن تتحقق من سلامة النسخة وإصدار المخطط قبل استبدال قاعدة البيانات المحلية.

## Google Drive

النسخ السحابي سيكون منفصلًا عن العمليات اليومية. فشل تسجيل الدخول أو انقطاع الإنترنت لا يمنع تسجيل دين جديد. شاشة النسخ الاحتياطي ستعرض آخر نسخة ناجحة بوضوح للمستخدم.

## الاختبارات

- Unit tests للحسابات والنماذج.
- Database tests للمعاملات والقيود.
- Widget tests للواجهات الأساسية.
- Integration tests لمسار: إنشاء زبون → تسجيل دين → تسديد → إعادة فتح التطبيق.
